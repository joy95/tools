# 链接口播文案提取设计

## 目标

在现有“链接解析”入口中新增口播文案提取能力。用户粘贴抖音、小红书或视频号短视频链接后，系统继续返回原有作品文案和媒体文件，并额外识别视频里的口播内容。

这里的“口播文案”指视频音频中的人声转写文本，不使用链接标题、描述或分享文案替代。

## 用户流程

1. 用户在链接解析页粘贴短视频链接或分享内容。
2. 前端按现有逻辑提交 `link_parse` 任务。
3. 后端解析并下载视频素材。
4. 如果作品包含本地 mp4 视频，后端提取音频并执行语音转文字。
5. 前端在结果区展示“作品文案”和“口播文案”，口播文案支持复制。

## 后端设计

继续使用现有 `link_parse` 任务类型，结果结构新增字段：

```json
{
  "caption": "平台作品文案",
  "speech_text": "视频中的口播文案",
  "speech_status": "success",
  "speech_message": ""
}
```

处理链路：

- 链接解析和素材下载沿用现有平台 extractor 与 `download_work_assets`。
- 新增语音处理器，输入为本地 mp4 文件路径。
- 使用 `ffmpeg` 从视频中提取音频。
- 新增 `faster-whisper` 作为本地 ASR 依赖，默认使用 `tiny` 模型，模型大小可通过配置调整。
- ASR 转写输出纯文本。
- 只对 `type == "video"` 且本地文件为 mp4 的 asset 执行口播提取。
- 图片作品跳过口播提取，返回 `speech_status: "skipped"`。

状态定义：

- `success`：识别成功，`speech_text` 有内容。
- `empty`：识别完成但没有有效人声文本。
- `skipped`：非视频作品或没有可处理视频。
- `failed`：口播识别失败，但链接解析和素材下载仍成功。

## 前端设计

链接解析页结果区新增“口播文案”卡片：

- 展示 `speech_text`。
- 有内容时显示“复制口播文案”按钮。
- `skipped` 时显示“当前作品无需提取口播文案”。
- `failed` 时显示 `speech_message`。
- 不影响现有视频预览、媒体下载和作品文案展示。

## 错误处理

- 口播识别失败不使整个 `link_parse` 任务失败。
- 视频解析或下载失败仍按现有任务失败逻辑处理。
- ASR 模型不可用、音频提取失败、音频无有效人声，都写入 `speech_status` 和 `speech_message`。

## 验证

后端：

- 视频 asset 成功转写时返回 `speech_status: "success"` 和 `speech_text`。
- 图片 asset 返回 `speech_status: "skipped"`。
- ASR 抛错时任务仍成功，返回 `speech_status: "failed"`。

前端：

- 构建通过。
- 链接解析成功后展示口播文案卡片。
- 口播文案复制按钮可用。
