# 自媒体工具箱小程序实施计划

## 1. 项目概述
本项目旨在开发一款全平台通用的自媒体工具箱微信小程序，提供去水印（图片/视频）、文案提取（图片）和图文生成视频三大核心功能，旨在提高自媒体创作者的工作效率。

## 2. 整体架构
*   **前端**: uni-app (基于 Vue.js)，运行在微信小程序环境。
*   **后端**: Python + FastAPI 服务，处理计算密集型任务。
*   **通信方式**: RESTful API。

## 3. 前端实施计划 (uni-app 微信小程序)

### 3.1 技术栈
*   **框架**: uni-app (Vue.js 3 + Composition API 优先)
*   **UI**: uni-ui (或兼容的第三方组件库，如 uView UI 2.x)
*   **状态管理**: Pinia (uni-app 推荐，比 Vuex 更轻量高效)
*   **网络请求**: uni.request 的封装，统一错误处理和请求拦截。
*   **文件上传**: uni.uploadFile

### 3.2 模块设计与开发步骤

#### 3.2.1 项目初始化与基础配置
1.  使用 `HBuilderX` 或 `Vue CLI` 初始化 uni-app 项目。
2.  配置 `uni-ui` 或选择的 UI 组件库。
3.  配置 `Pinia` 状态管理。
4.  封装 `uni.request`，实现统一的请求拦截、错误处理、加载状态管理。

#### 3.2.2 首页/功能列表页
1.  设计并实现首页布局，展示“去水印”、“文案提取”、“图文生成视频”三个主要功能入口。
2.  各功能入口可使用图标 + 文字形式，点击跳转到相应的功能页面。

#### 3.2.3 去水印功能页 (链接/上传文件)
1.  **UI 布局**:
    *   **链接输入区域**: 文本框供用户粘贴抖音、小红书、视频号等平台的分享链接。
    *   **文件选择区域 (可选)**: 按钮触发 `uni.chooseImage` (图片) / `uni.chooseVideo` (视频)，作为备用方案。
    *   上传进度展示：当文件较大时，显示上传进度条。
    *   结果展示区域：去水印后的图片或视频预览。
    *   操作按钮：下载结果文件、分享结果。
2.  **逻辑实现**:
    *   用户在文本框粘贴链接后，前端进行基本校验，然后调用后端 `/api/watermark/remove` 接口，传入链接 (如果链接有效)。
    *   如果用户选择上传文件 (备用方案)，则调用封装的上传方法，将文件上传到后端 `/api/watermark/remove` 接口。
    *   接收后端返回的去水印后的文件 URL 或任务 ID，并在页面中展示。
    *   实现文件下载 (`uni.downloadFile`) 和分享功能。
    *   考虑大文件上传和处理过程中的 loading 状态及错误提示。

#### 3.2.4 文案提取功能页 (链接/上传图片)
1.  **UI 布局**:
    *   **链接输入区域**: 文本框供用户粘贴抖音、小红书、视频号等平台的分享链接。
    *   **图片选择区域 (可选)**: 按钮触发 `uni.chooseImage`，作为备用方案。
    *   上传进度展示。
    *   结果展示区域：可编辑的文本框，显示提取的文案。
    *   操作按钮：复制文案。
2.  **逻辑实现**:
    *   用户在文本框粘贴链接后，前端进行基本校验，然后调用后端 `/api/text/extract` 接口，传入链接 (如果链接有效)。
    *   如果用户选择上传图片 (备用方案)，则调用封装的上传方法，将图片上传到后端 `/api/text/extract` 接口。
    *   接收后端返回的文案内容，更新文本框。
    *   实现复制文案到剪贴板功能 (`uni.setClipboardData`)。

#### 3.2.5 图文生成视频功能页
1.  **UI 布局**:
    *   图片上传区域：支持多张图片选择 (`uni.chooseImage`，限制数量)。
    *   文案输入框：用户输入视频文案。
    *   模板选择 (可选，初期可简化为默认模板)。
    *   配音/背景音乐选择 (初期可简化)。
    *   生成按钮。
    *   生成进度展示。
    *   结果展示区域：生成后的视频预览。
    *   操作按钮：下载视频、分享视频。
2.  **逻辑实现**:
    *   调用 `uni.chooseImage` 选择多张图片。
    *   获取用户输入的文案。
    *   调用后端 `/api/video/generate` 接口，发送图片列表、文案等参数。
    *   接收后端返回的任务 ID，前端轮询任务状态或通过 WebSocket 接收推送。
    *   任务完成后，接收后端返回的视频 URL，并在页面中展示。
    *   实现视频下载和分享功能。

#### 3.2.6 文件上传与下载管理模块
1.  统一的文件上传函数，处理 `uni.uploadFile` 的请求头、参数、进度回调和错误处理。
2.  统一的文件下载函数，处理 `uni.downloadFile` 的下载进度和结果。

### 3.3 前端测试策略
*   **单元测试**: 使用 `uni-app` 官方推荐的 `Jest` 对 Vue 组件和工具函数进行单元测试。
*   **集成测试**: 模拟用户操作流程，确保各功能页面及与后端交互的正确性。
*   **真机调试**: 在微信开发者工具和真实手机上进行全面测试，确保兼容性和性能。

## 4. 后端实施计划 (Python FastAPI)

### 4.1 技术栈与环境
*   **Python 版本**: 3.8+
*   **Web 框架**: FastAPI
*   **ASGI 服务器**: Uvicorn (配合 Gunicorn 生产部署)
*   **异步任务队列**: Celery + Redis (作为 Broker 和 Backend)
*   **文件存储**: 本地文件系统 (初期)
*   **依赖管理**: Poetry 或 Pipenv
*   **开发环境**: Docker + Docker Compose

### 4.2 模块设计与开发步骤

#### 4.2.1 项目初始化与基础配置
1.  初始化 Python 项目，配置 `Poetry` 或 `Pipenv`。
2.  安装 `FastAPI`, `Uvicorn`, `python-multipart` (处理文件上传)。
3.  搭建 `Docker Compose` 环境，包含 `FastAPI` 服务、`Redis`、`Celery worker`。
4.  编写基础的 `main.py` 和 `app/api/v1` 路由结构。
5.  配置 `logging` 模块，实现日志记录。

#### 4.2.2 Link 解析与内容抓取服务
1.  **核心任务**: 负责解析抖音、小红书、视频号的分享链接，获取原始图片/视频 URL 和文案。
2.  **技术选型**:
    *   `requests` (HTTP 请求库)
    *   `BeautifulSoup` 或 `lxml` (HTML 解析库)
    *   可能需要针对不同平台编写特定的解析逻辑 (例如，针对抖音分享链接的重定向、小红书的 meta 标签提取等)。
    *   **高难度/备选方案**: 如果遇到强反爬机制，可能需要研究使用 `playwright` 或 `selenium` 进行无头浏览器抓取 (会增加部署复杂度和资源消耗)。
3.  **挑战与风险**:
    *   **反爬机制**: 各平台会持续更新反爬策略，需要持续投入维护。
    *   **法律合规性**: 抓取和处理第三方内容需注意版权、隐私和服务协议，确保合法合规。
    *   **维护成本**: 平台接口变化可能导致解析逻辑失效，需要及时更新。

#### 4.2.3 文件管理服务
1.  **文件上传接口**:
    *   `POST /upload`: 接收文件，保存到本地临时目录，返回文件路径或 URL。
    *   实现文件类型的校验和大小限制。
2.  **文件下载服务**:
    *   `GET /files/{filename}`: 提供静态文件服务，允许前端下载处理结果文件。

#### 4.2.4 去水印 API (`/api/watermark`)
1.  **`POST /watermark/remove`**:
    *   **请求**: 接收图片/视频文件 或 `url` (分享链接)。
    *   **处理**:
        *   如果请求中包含 `url`，则首先调用“Link 解析与内容抓取服务”获取原始文件 URL 或文件流。
        *   如果获取到文件 URL，则下载文件到本地进行后续处理。
        *   如果请求中直接包含文件，则保存到本地。
        *   如果是图片，直接调用图片去水印函数。
        *   如果是视频，将去水印任务提交给 Celery，返回任务 ID。
    *   **图片去水印函数**:
        *   利用 `OpenCV` 和 `Pillow` 进行图像处理。
        *   集成开源的去水印算法（例如，基于图像修复或内容填充）。初期可尝试简单的基于颜色或纹理识别的水印去除方法，后续根据效果优化。
    *   **视频去水印任务 (Celery)**:
        *   分解视频为帧 (`OpenCV`)。
        *   对每一帧调用图片去水印函数。
        *   将处理后的帧重新合成视频 (`MoviePy`)。
        *   保存处理后的视频文件到本地。
    *   **响应**: 去水印后的文件 URL 或 Celery 任务 ID。

#### 4.2.5 文案提取 API (`/api/text`)
1.  **`POST /text/extract`**:
    *   **请求**: 接收图片文件 或 `url` (分享链接)。
    *   **处理**:
        *   如果请求中包含 `url`，则首先调用“Link 解析与内容抓取服务”获取原始图片 URL 或文件流。对于文案，可能直接从解析服务中获取（例如，小红书笔记的文案）。
        *   如果获取到文件 URL，则下载图片到本地。
        *   如果请求中直接包含图片文件，则保存到本地。
        *   调用 `PaddleOCR` 或 `EasyOCR` 库进行文本识别（如果需要从图片中提取）。
    *   **响应**: 提取的文案文本。

#### 4.2.6 图文生成视频 API (`/api/video`)
1.  **`POST /video/generate`**:
    *   **请求**: 接收多张图片文件、文案、模板ID (可选)、配音选择 (可选)。
    *   **处理**:
        *   将图片和文案保存到本地。
        *   将视频生成任务提交给 Celery，返回任务 ID。
    *   **视频生成任务 (Celery)**:
        *   根据模板和文案，编排图片展示顺序和时长。
        *   **文本转语音 (TTS)**: 使用 `gTTS` 将文案转换为音频文件。
        *   **视频合成**: 利用 `MoviePy` 将图片、配音、背景音乐、文字动效、转场效果等元素合成视频。
        *   保存生成的视频文件到本地。
    *   **响应**: Celery 任务 ID。
2.  **`GET /video/status/{task_id}`**:
    *   **请求**: 接收 Celery 任务 ID。
    *   **处理**: 查询 Celery 任务状态。
    *   **响应**: 任务状态 (如 `PENDING`, `STARTED`, `SUCCESS`, `FAILURE`) 和结果 URL (如果成功)。

#### 4.2.7 认证与鉴权
1.  实现简单的 API Key 或 Token 认证中间件，保护所有 API 接口。

### 4.3 后端测试策略
*   **单元测试**: 使用 `pytest` 对各个函数和类进行单元测试，覆盖核心算法和业务逻辑。
*   **集成测试**: 编写测试用例，模拟前端请求，测试 API 接口的正确性，包括文件上传/链接解析、任务提交、结果查询等。
*   **性能测试**: 对关键 API (如去水印、视频生成) 进行性能测试，评估并发处理能力和响应时间，并针对性优化。
*   **端到端测试**: 部署整个前后端系统，模拟真实用户场景，验证整个流程的正确性。
*   **链接解析稳定性测试**: 定期针对抖音、小红书、视频号的链接进行自动化测试，确保解析逻辑的稳定性和有效性。

## 5. 部署建议
1.  **本地开发**: 使用 Docker Compose 快速搭建开发环境。
2.  **生产部署**:
    *   **服务器**: 选用配置适中的云服务器 (CPU 2核, 内存 4GB 起，硬盘 100GB+)。
    *   **部署方式**: Docker 容器化部署。使用 `Docker Compose` 管理 `FastAPI` 服务、`Uvicorn`、`Nginx` (作为反向代理和静态文件服务)、`Redis`、`Celery worker`。
    *   **域名与 HTTPS**: 配置域名，并启用 HTTPS。
    *   **持续集成/部署 (CI/CD)**: 可考虑使用 GitLab CI/CD、GitHub Actions 等工具实现自动化部署。

## 6. 后续优化与扩展
*   **功能优化**: 提升去水印、文案提取、视频生成的效果和速度。
*   **模板库**: 增加更多视频模板，并允许用户自定义模板。
*   **AI 增强**: 引入更高级的 AI 算法，如智能剪辑、内容推荐、风格迁移等。
*   **用户管理**: 增加用户注册、登录、个人中心功能，管理用户生成的内容。
*   **多平台支持**: 将 uni-app 扩展到抖音、快手等其他小程序平台。
*   **成本优化**: 随着用户量增长，评估并优化云服务成本，如采用按需扩容、Serverless 等。
*   **缓存策略**: 对不经常变动的数据或计算结果进行缓存，减少重复计算。
*   **反爬机制应对**: 持续关注并更新链接解析模块，以应对平台反爬机制的升级。
